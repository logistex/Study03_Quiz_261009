카테고리 4개(한국사, 세계지리, 과학, 예술과 문화)에 새 문항을 n개씩 만든다. n은 `$ARGUMENTS`이다.

## 지킬 것

- n이 1~5의 정수가 아니면 아무것도 하지 않고 "n은 1~5의 정수로 적어 주십시오."라고 알린 뒤 멈춘다
- 카테고리마다 정확히 n개를 만든다. 카테고리마다 문항 수가 같아야 한다(PRD.md 1절, 6.3항)
- 승인을 받기 전에는 어떤 파일도 고치지 않는다
- 커밋하지 않는다

## 1단계: 문항 만들기

1. CLAUDE.md의 「문항 작성 규칙」 10개를 읽는다. 규칙 문구는 매번 파일에서 읽고, 이 명령어에 적힌 요약에 기대지 않는다
2. PRD.md 6.1항(데이터 형식)과 6.2항(출처 표기)을 읽는다
3. questions.js를 처음부터 끝까지 읽고, 카테고리별 마지막 id 번호와 이미 다룬 주제를 확인한다
4. 카테고리마다 n개를 만든다
   - 기존 문항과 같은 사실을 묻지 않는다
   - id는 카테고리 약자(`kh`, `wg`, `sc`, `ac`)와 마지막 번호의 다음 번호로 적는다. 예: `kh-11`
   - 오답 3개도 정답과 같은 유형으로 만든다(규칙 7)
5. 문항마다 출처 2개를 확인한다
   - 두 출처는 서로 다른 기관의 자료이고, 한쪽이 다른 쪽을 옮겨 적은 자료가 아니어야 한다
   - 두 페이지를 모두 실제로 열어, 문제 문장, 정답, 해설에 쓴 사실(연도, 인물, 장소, 수치)을 하나씩 대조한다
   - 검색 결과의 요약만 보고 확인한 것으로 치지 않는다
   - 두 출처에 모두 있는 사실만 문제와 해설에 쓴다. 출처끼리 값이 다르면 그 값은 쓰지 않는다(규칙 4)
   - 위키백과, 나무위키, 블로그, 카페는 출처로 쓰지 않는다
   - source는 `"자료명, URL, 확인한 날짜"` 문자열 2개의 배열로 적는다. 날짜는 실제로 페이지를 연 날이다
6. 출처를 확인하지 못한 문항은 버리고 다른 문항으로 바꿔 n개를 채운다. 끝내 n개를 채우지 못한 카테고리가 있으면 어떤 문항도 넣지 않고, 어느 카테고리에서 몇 개가 모자랐는지 알린 뒤 멈춘다
7. 만든 문항마다 규칙 1~10을 다시 확인한다. 특히 정답이 하나인지(규칙 1), 정답과 해설이 맞는지(규칙 6)를 확인한다

## 2단계: 보여 주기

첫 줄에 결과를 한 줄로 적는다. 예: `카테고리마다 3개, 모두 12문항을 만들었음. 아직 questions.js에 넣지 않았음`

카테고리마다 표 1개로 보여 준다.

| id | 문제 | 보기(정답 표시) | 해설 | 출처 2개 | 대조한 구절 |
|---|---|---|---|---|---|

- 「대조한 구절」에는 문제와 해설의 사실마다 두 페이지에서 그대로 옮긴 짧은 구절을 적는다
- 버리고 바꾼 문항이 있으면 표 아래에 그 이유를 적는다
- 마지막에 "모두 넣을지, 바꿀 문항이 있는지 알려 주십시오."라고 묻고 차례를 끝낸다

## 3단계: 넣기(승인을 받은 뒤에만)

- 일부만 승인하면, 거절한 문항만 1단계 절차로 새로 만들어 2단계 형식으로 다시 보여 준다. 카테고리마다 n개가 모두 승인될 때까지 넣지 않는다
- 모두 승인하면 questions.js의 각 카테고리 블록 끝에 넣는다. 기존 문항과 같은 형식(들여쓰기, 따옴표, source 배열)을 따른다
- 넣은 뒤 다음 2가지를 실행하고 결과를 보여 준다
  - IMPL-PLAN.md Task 1 Step 5의 Node 문항 검사. 기대 출력: `문항 검사 통과: N문항`(N은 넣은 뒤의 전체 문항 수)
  - `node script.js`. 기대 출력의 끝 줄: `점검 통과: N개`
- 하나라도 실패하면 넣은 문항을 모두 빼서 questions.js를 넣기 전 상태로 되돌린다
  - 되돌린 뒤 Node 문항 검사와 `node script.js`를 다시 실행해 넣기 전과 같은 결과가 나오는지 확인한다
  - 실패한 검사의 출력과 되돌린 결과를 알린다. 문항을 임의로 고쳐 다시 넣지 않는다
